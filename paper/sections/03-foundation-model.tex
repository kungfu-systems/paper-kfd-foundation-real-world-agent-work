\section{The Foundation: Facts, Trust, and Cooperation}
\label{sec:foundation}

KFD-1/2/3 form the foundation of the model. Their order is load-bearing, and
their scope is more general than any single implementation schema.

\subsection{KFD-1: facts must not drift}

A \emph{contract world} is the set of surfaces to which another participant
can weld at integration time or across time: schemas, ABIs, configuration
semantics, CLI behavior, persisted records, release channels, and public
document routes. Let $W$ identify a declared contract world, $F_W$ its fact
source, and $c$ its explicit compatibility boundary. KFD-1 requires:

\begin{equation}
W_t = W_{t'} \land c_t = c_{t'} \Longrightarrow
\operatorname{meaning}(F_{W,t}) = \operatorname{meaning}(F_{W,t'}).
\end{equation}

The equation does not freeze a system forever. It says that semantic change
must cross a declared boundary instead of silently reusing the same coordinate.
The practical mechanism is a welded-surface register and a final-diff
classification: breaking, additive, no registered-surface impact, or
unclassifiable. Unclassifiable means the register is deficient; it is not
permission to guess.

KFD-1 is therefore an ontology for load-bearing facts. A fact is not made
stable merely because it is written in JSON or committed to Git. Its source,
meaning, consumer weld, and change boundary must be declared.

\subsection{KFD-2: trust must start from facts}

Trust is not a property attached to an object in the abstract. It is an
assessment of a claim $C$ for a purpose $P$ over a fact and evidence cut. We
model a trust assessment as:

\begin{equation}
T = \mathcal{A}(C, P, F, E, R, Q),
\end{equation}

where $F$ is the pinned fact set, $E$ the checked evidence, $R$ residual risk,
and $Q$ the responsibility assignment for source, verification, and decision.
The result is not necessarily binary; pass, warning, fail, and unverifiable
are useful distinct outcomes.

KFD-2 prevents a summary, successful command, agent self-report, or maintainer
reputation from silently becoming proof. The same structure can assess a
release, configuration, API, timeline, collaboration interface, runtime fact,
or completion claim. Local and exportable evidence is preferred where the
system can capture it, because a cloud control surface should not become the
only place where operational truth exists.

\subsection{KFD-3: cooperation must start from trusted value}

Facts and trust do not automatically produce cooperation. A system can expose
correct evidence while still using hidden constraints or forced workflow
capture. KFD-3 requires an intelligent participant to be able to inspect the
offered value, its factual basis, the available choices, and the applicable
constraints before cooperation is requested.

Let $V$ be a value claim, $T(V)$ its trust assessment, $K$ the visible
constraints, and $O$ the available options. Cooperation is durable only when
these are exposed to the participant:

\begin{equation}
\operatorname{Cooperate} = g(V, T(V), K, O, \text{record}).
\end{equation}

This is not a rejection of strong constraints. Sandboxes, permissions,
revocation, and refusals remain necessary. KFD-3 rejects constraints whose
operation or justification is hidden from the reasoning participant. A human
may prefer a GUI and an agent structured data, but neither should receive a
weaker truth world.

\subsection{The ordered chain}

The foundation is:

\begin{equation}
\text{non-drifting facts}
\rightarrow \text{inspectable trust}
\rightarrow \text{trusted value}
\rightarrow \text{cooperation}
\rightarrow \text{reviewable record}.
\end{equation}

If KFD-1 fails, trust binds to unstable facts. If KFD-2 fails, value rests on
uninspectable claims. If KFD-3 fails, a factually correct system can still
obtain compliance by capture. The reviewable record feeds later fact and trust
assessment, making the chain capable of self-correction.

KFD-4/5/6 do not enlarge this foundation with unrelated axioms. They are
procedures for applying it to perspective, primitive discovery, and autonomous
learning. That distinction keeps the foundation compact while allowing the
system to grow operationally.
